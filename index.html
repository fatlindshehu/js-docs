Core Part 1

The core of the language: values, variables, operators and decisions. Start at the top or jump to any page.

    Running JavaScript

    Connecting a script to a page, printing output and writing comments.

    JavaScript runs in the browser. To run your own code, you link a .js file to an HTML page.

    1

    Linking a JavaScript file

    Add a <script> tag with the file path in src. Put it at the end of <body>, so the HTML above it already exists when the script runs.

    <body>
  <h1>My page</h1>

  <script src="script.js"></script>
</body>
    2

    console.log output

    console.log() prints a value to the browser console. Open it with F12 or right-click → Inspect → Console. Separate several values with commas to print them on one line.

    console.log("Script loaded");  // Script loaded
console.log(40 + 8 + 23 - 10);  // 61
console.log("Total:", 61);      // Total: 61
    3

    Comments

    Comments are notes in the code. JavaScript ignores them. They are also used to switch code off temporarily.

    // A single-line comment

/* A comment
   over several lines */

// console.log("This line does not run");

    An object is a value that groups other values together. Every value that is not a primitive is an object.

    TypeHoldsExample

    Variables

    Storing values under a name so you can use them later.

    A variable is a name that points to a value. You declare it once, then use the name wherever you need the value.

    1

    Declaring a variable

    let creates the variable, = assigns a value to it. After that, the name stands for the value.

    let city = "Berlin";

console.log(city);  // Berlin
console.log(city);  // Berlin

city = "Hamburg";   // assign a new value
console.log(city);  // Hamburg
    2

    JavaScript chooses the type

    JavaScript is a dynamically typed language. You never write a type when you declare a variable. JavaScript looks at the value and decides the type itself.

    let age = 30;          // JavaScript decides: number
let city = "Berlin";   // JavaScript decides: string
let isOpen = true;     // JavaScript decides: boolean

    Because the type belongs to the value and not to the variable, the same variable can later hold a value of a different type.

    let answer = 42;       // number
answer = "forty-two";  // now a string, no error

    In statically typed languages such as Java or C, you write the type yourself and it cannot change: int age = 30;. TypeScript adds this to JavaScript. How to check a type: Data types and typeof.

    3

    Breaking one of these rules is a SyntaxError, and the code does not run.

    Cannot start with a digitlet item3let 3items
    Cannot be a reserved wordlet $functionlet function
    Case-sensitiveage and Age are two different variables—

    Naming conventions

    These are not enforced, but every JavaScript codebase follows them.

    ConventionDoAvoid
    camelCase: first word lowercase, each next word capitalisedlet firstNamelet first_name
    Descriptive nameslet currentJoblet job2
    UPPERCASE for fixed constants known before the program runsconst PI = 3.1415const pi = 3.1415

    Statements and expressions

    The difference between code that produces a value and code that performs an action.

    JavaScript code is made of two kinds of pieces:

    1. An expression produces a value.
    2. A statement performs an action. It does not produce a value on its own.
    1

    Examples

    A statement often contains expressions.

    CodeKindValue produced
    3 + 4Expression7
    1995Expression1995
    true && false && !falseExpressionfalse
    age >= 18Expressiontrue or false
    const total = 3 + 4;Statement, containing the expression 3 + 4—
    if (age >= 18) { … }Statement—
    switch (day) { … }Statement—
    2

    What a statement does

    A statement is an instruction that tells JavaScript to do something. A program is a list of statements, run one after another from top to bottom.

    StatementWhat it does
    const total = 3 + 4;Creates a variable and stores a value in it
    if (age >= 18) { … }Decides which block of code runs
    switch (day) { … }Picks one case to run, based on a value
    for (…) { … }Repeats a block of code
    return total;Ends a function and sends a value back
    console.log(total);Runs an expression as an instruction, here printing a value

    A statement does not produce a value

    An expression gives you a value you can use somewhere else: store it, print it, pass it on. A statement does not. You cannot store an if in a variable.

    const result = 3 + 4;            // fine, 3 + 4 produces 7
const result2 = if (true) {};    // SyntaxError, if produces no value

    Statements contain expressions

    Most statements have expressions inside them. The statement is the action, and the expressions supply the values the action needs.

    const total = 3 + 4;
// statement:  const total = ... ;   (creates the variable)
// expression: 3 + 4                 (produces 7)

if (total > 5) {
  console.log("Big");
}
// statement:  if (...) { ... }      (decides what runs)
// expression: total > 5             (produces true)

    Declaration vs assignment

    A declaration with const or let is a statement. An assignment without a keyword is an expression: it produces the assigned value. That is why a = b = 10 works: b = 10 produces 10, which is then assigned to a.

    CodeKind
    3 + 4Expression, produces 7
    const total = 3 + 4;Statement (declaration), produces no value
    total = 7Expression (assignment), produces 7
    total = 7;That expression used as a statement

    Expression statements

    Any expression followed by a semicolon can stand on its own as a statement. It then runs as an instruction, and its value is thrown away.

    let total = 0;

console.log("Hi");  // a function call used as a statement
total = 5;          // an assignment used as a statement
3 + 4;              // valid, but useless: the 7 is thrown away

    A simple test: if you could put the code on the right side of const value = …, it is an expression. If not, it is a statement.

    3

    Why it matters

    Some places accept only expressions. The most common one is ${ } in a template literal.

    const year = 2030;

console.log(`Age: ${year - 1995}`);      // works, an expression

console.log(`${if (year > 2000) {}}`);   // SyntaxError, if is a statement

    This is why the ternary operator exists: it is an if / else written as an expression. See The ternary operator.

    let, const and var

    The three keywords for declaring variables, and when to use each.

    Use const by default. Use let only when the value has to change. Don't use var.

    1

    Comparison

    The main difference is whether you can assign a new value later.

    KeywordReassignValue required at declarationUse for
    constNoYesValues that stay the same (default choice)
    letYesNoValues that change, such as a counter
    varYesNoOld code only. Avoid in new code
    2

    let

    A let variable can be reassigned, and it can be declared empty.

    let score = 10;
score = 15;       // fine

let level;        // fine, the value is undefined for now
level = 1;
    3

    const

    A const variable must get its value immediately, and it cannot be reassigned.

    const birthYear = 1995;
birthYear = 1996;  // TypeError: Assignment to constant variable.

const country;     // SyntaxError: Missing initializer in const declaration

    const prevents reassigning the variable. It does not freeze an object or array: const list = [1, 2]; list.push(3); works.

    4

    var

    var is the way variables were declared before 2015. It still works, but it is scoped to functions instead of blocks, which causes bugs. Use let instead.

    var total = 5;
total = 8;  // works, but prefer let
    5

    Forgetting the keyword

    Assigning to a name that was never declared does not create a normal variable. In regular scripts it silently creates a global variable. In strict mode and in modules it throws an error. Always declare with const or let.

    lastName = "Weber";  // no const, let or var
console.log(lastName);  // Weber, but it is now a global variable

// in strict mode or a module:
// ReferenceError: lastName is not defined

    Data types and typeof

    Checking the type of a value, and how variables can hold different types over time.

    The typeof operator returns the type of a value as a string.

    1

    What typeof returns

    Most results match the type name. Three are surprising: null, arrays and functions.

    ExpressionResult
    typeof 42"number"
    typeof 3.14"number"
    typeof "hello""string"
    typeof true"boolean"
    typeof 10n"bigint"
    typeof undefined"undefined"
    typeof Symbol("id")"symbol"
    typeof null"object" (a bug in the language, null is a primitive)
    typeof {}"object"
    typeof []"object" (arrays are objects)
    typeof function () {}"function" (functions are objects too)
    2

    Dynamic typing

    JavaScript decides the type from the value, and the type belongs to the value, not to the variable. A variable can hold a number now and a string later. typeof shows the type at each moment.

    let isReady = true;
console.log(typeof isReady);  // "boolean"

isReady = "yes";
console.log(typeof isReady);  // "string"
    3

    Declared but empty

    A variable declared without a value holds undefined. Its type is also "undefined" until you assign something.

    let year;
console.log(year);         // undefined
console.log(typeof year);  // "undefined"

year = 2030;
console.log(typeof year);  // "number"

    Operator precedence

    Which operator runs first when one expression has several.

    Precedence decides which operator runs first. Associativity decides the direction when operators have the same precedence: left to right, or right to left.

    1

    The order, from first to last

    A simplified list of the operators covered so far. Operators higher in the table run first.

    RunsOperatorsDirection
    1st( ) grouping—
    2nd! ++ -- typeofright to left
    3rd**right to left
    4th* / %left to right
    5th+ -left to right
    6th< <= > >=left to right
    7th=== !== == !=left to right
    8th&&left to right
    9th|| ??left to right
    10th? : ternaryright to left
    Last= += -= *= …right to left

    Full table: MDN operator precedence.

    2

    Examples

    Maths runs before comparison, multiplication before addition, and parentheses before everything.

    const now = 2030;
now - 1995 > now - 2012;  // both subtractions first: 35 > 18, so true

2 + 3 * 4;    // 14, multiplication first
(2 + 3) * 4;  // 20, parentheses first
    3

    Assignment runs right to left

    This is why you can assign one value to several variables in one line.

    let a, b;
a = b = 25 - 10 - 5;
// 1. 25 - 10 - 5 runs left to right: 10
// 2. = runs right to left: b = 10, then a = b, so a = 10
console.log(a, b);  // 10 10
    4

    Using parentheses

    Without parentheses, / would run before +.

    const ageAnna = 35;
const ageTom = 18;

const wrong = ageAnna + ageTom / 2;    // 35 + 9 = 44
const average = (ageAnna + ageTom) / 2; // 53 / 2 = 26.5

    Strings and template literals

    Writing text values and building strings that include other values.

    A string is text in quotes. JavaScript accepts three kinds of quotes:

    1. Single quotes: 'hello'
    2. Double quotes: "hello"
    3. Backticks: `hello`, called template literals
    1

    Concatenation vs template literals

    With +, you have to close and reopen quotes and add spaces yourself. A template literal lets you write the sentence once and insert values with ${...}.

    const name = "Lena";
const job = "designer";
const birthYear = 1998;
const year = 2030;

const intro1 = "I'm " + name + ", a " + (year - birthYear) + " year old " + job + "!";
const intro2 = `I'm ${name}, a ${year - birthYear} year old ${job}!`;

console.log(intro1);  // I'm Lena, a 32 year old designer!
console.log(intro2);  // I'm Lena, a 32 year old designer!
    2

    What goes inside ${ }

    Any expression: a variable, a calculation, a function call, a comparison. Statements such as if are not allowed.

    const price = 20;
console.log(`Total: ${price * 3} €`);       // Total: 60 €
console.log(`Expensive: ${price > 50}`);    // Expensive: false

    Why only expressions: see Statements and expressions.

    3

    Multi-line strings

    With normal quotes you need \n for a line break. Template literals keep the line breaks as you type them.

    console.log("Line one\nLine two\nLine three");

console.log(`Line one
Line two
Line three`);

    if / else

    Running different code depending on a condition.

    An if statement runs a block of code only when its condition is true. The optional else block runs when it is false.

    1

    if / else

    The condition goes in parentheses. The code to run goes in curly braces.

    const age = 16;

if (age >= 18) {
  console.log("You can get a driving licence.");
} else {
  const yearsLeft = 18 - age;
  console.log(`Wait another ${yearsLeft} years.`);
}
// Wait another 2 years.
    2

    else if

    Use else if to check several conditions. They are checked from top to bottom. The first true one runs, and the rest are skipped.

    const score = 82;

if (score >= 90) {
  console.log("Grade A");
} else if (score >= 75) {
  console.log("Grade B");   // this one runs
} else if (score >= 60) {
  console.log("Grade C");   // skipped, even though it is also true
} else {
  console.log("Failed");
}
    3

    Variables inside a block

    A variable declared with let or const inside { } only exists inside that block. To use the result afterwards, declare the variable before the if.

    const birthYear = 2004;

let century;            // declared outside
if (birthYear <= 2000) {
  century = 20;
} else {
  century = 21;
}
console.log(century);   // 21

if (true) {
  const message = "inside";
}
console.log(message);   // ReferenceError: message is not defined

    Turning a value of one type into another, on purpose or automatically.

    There are two ways a value changes type:

    1. Type conversion: you convert it yourself, for example with Number().
    2. Type coercion: JavaScript converts it automatically when an operator needs a different type.
    1

    Type conversion

    Use Number(), String() or Boolean().

    CodeResult

    Number("")0
    Number("hello")NaN
    String(42)"42"
    Boolean(0)false
    const inputYear = "1995";  // text from a form field is always a string

console.log(Number(inputYear) + 18);  // 2013
    2

    NaN

    NaN means "Not a Number". It is the result of a number operation that failed. Its type is still "number".

    console.log(Number("hello"));  // NaN

    The rule to remember: + with a string turns the other value into a string. -, * and / turn strings into numbers, and so does comparing a string with a number.

    Truthy and falsy values

    How JavaScript treats any value as true or false when it needs a boolean.

    When JavaScript needs a boolean but gets another value, it converts it. A value that becomes true is truthy. A value that becomes false is falsy.

    1

    The 8 falsy values

    There are exactly 8 falsy values. Every other value is truthy.

    Falsy (only these 8)
    1. false
    2. 0
    3. -0
    4. 0n
    5. ""
    6. null
    7. undefined
    8. NaN
    Truthy (everything else), for example
    • true
    • 42
    • -1
    • "hello"
    • "0"
    • "false"
    • " "
    • []
    • {}

    Watch out: "0", "false" and " " are non-empty strings, so they are truthy. An empty array [] and an empty object {} are objects, so they are truthy too.

    2

    Checking a value

    Boolean(value) shows how a value is treated.

    Boolean("hello");   // true
Boolean("");        // false
Boolean(0);         // false
Boolean(undefined); // false
Boolean({});        // true
    3

    Where the conversion happens

    JavaScript converts to a boolean in an if condition, with the logical operators &&, ||, !, and in the ternary operator.

    const balance = 250;

if (balance) {
  console.log("You have money left");  // runs, 250 is truthy
} else {
  console.log("Your balance is empty");
}
    4

    Pitfall: 0 is a real value

    A check like if (height) also fails when the value is 0, even though 0 may be valid. Compare explicitly when 0 or an empty string is allowed.

    let height = 0;

if (height) {
  console.log("Height is set");
} else {
  console.log("Height is not set");  // runs, but 0 is a valid height
}

if (height !== undefined) {
  console.log("Height is set");      // runs, correct
}

    Equality: == vs ===

    Checking whether two values are equal, with and without type coercion.

    JavaScript has two equality operators:

    1. === strict equality: true only if the value and the type are the same. No coercion.
    2. == loose equality: converts the types first, then compares.
    1

    Strict vs loose

    Loose equality gives results that are easy to get wrong.

    Expression=====
    "18" vs 18falsetrue
    0 vs ""falsetrue
    0 vs falsefalsetrue
    null vs undefinedfalsetrue
    18 vs 18truetrue
    2

    Not equal

    !== is the strict opposite of ===. != is the loose opposite of ==.

    const guess = 7;

if (guess !== 3) console.log("Not 3");  // Not 3
    3

    Rule: always use === and !==

    If types might differ, convert explicitly first. Then the comparison does exactly what you read.

    const input = "7";             // form input is always a string

if (input === 7) {}             // false, string vs number
if (input == 7) {}              // true, but only because of hidden coercion
if (Number(input) === 7) {}     // true, and the conversion is visible
    const guess = Number("7");

if (guess === 3) {
  console.log("3 is my favourite too");
} else if (guess === 7) {
  console.log("7 is a good number");   // this one runs
} else {
  console.log("Not 3 or 7");
}

    Boolean logic

    Combining true and false with three logical operators.

    JavaScript has 3 logical operators:

    1. && AND
    2. || OR
    3. ! NOT
    1

    && AND

    Returns true only when both sides are true. If one side is false, the result is false.

    ABA && B
    truetruetrue
    truefalsefalse
    falsetruefalse
    falsefalsefalse
     
    const hasTicket = true;

hasTicket && isAdult; // false: both must be true
    2

    || OR

    Returns true when at least one side is true. Only false || false gives false.

    ABA || B
    truetruetrue
    truefalsetrue
    falsetruetrue
    falsefalsefalse
     
    const isWeekend = false;

    3

    ! NOT

    Flips a value: true becomes false, false becomes true. It works on one value only.

    A!A
    truefalse

    4

    Combining operators in conditions

    Logical operators are mostly used inside if conditions, and you can chain several.

    const hasLicense = true;

if (hasLicense && hasGoodVision && !isTired) {
  console.log("You can drive.");       // runs

}

    && runs before ||, so a || b && c means a || (b && c). Use parentheses when mixing them. See Operator precedence.

    5

    With values that are not booleans

    So far A and B were always true or false. In JavaScript you can use the logical operators with any value: numbers, strings, objects, null. What happens depends on short-circuiting.

    This builds on truthy and falsy values: when an operator needs a boolean, any value is treated as true (truthy) or false (falsy). Only 8 values are falsy: false, 0, -0, 0n, "", null, undefined, NaN.

    Step 1: && and || return a value, not a boolean

    JavaScript reads a logical expression from left to right and stops as soon as it knows the answer. This is called short-circuiting. The result is the value where it stopped, unchanged. It is not converted to true or false.

    The two short-circuit rules:

    1. && returns the first falsy value it encounters. If all values are truthy, it returns the last value.
    2. || returns the first truthy value it encounters. If all values are falsy, it returns the last value.
    && AND
    1. Look at the left value.
    2. If it is falsy, the answer is already false. Stop and return the left value.
    3. Otherwise, return the right value.

    Returns the first falsy value, or the last value if none is falsy.

    || OR
    1. Look at the left value.
    2. If it is truthy, the answer is already true. Stop and return the left value.
    3. Otherwise, return the right value.

    Returns the first truthy value, or the last value if none is truthy.

    const stock = 12;
const emptyStock = 0;

stock && "In stock";       // "In stock"  12 is truthy, so && returns the right value
emptyStock && "In stock";  // 0           0 is falsy, so && stops and returns 0

const username = "";
const savedName = "anna_k";

username || "Guest";        // "Guest"     "" is falsy, so || returns the right value
savedName || "Guest";       // "anna_k"    left is truthy, so || stops and returns it

    Examples with more than two values

    With more operands, the same rule repeats from left to right. Each value is checked in turn until one decides the result.

    Step 2: the right side may never run

    When JavaScript stops at the left value, it does not evaluate the right side at all. If the right side is a function call, that function is not called.

    function sayHi() {
  console.log("Hi");
  return true;
}

false && sayHi();  // false, and "Hi" is never logged
true  || sayHi();  // true,  and "Hi" is never logged
true  && sayHi();  // logs "Hi", returns true

    ! always returns a boolean

    ! is different from the other two. It first treats the value as truthy or falsy, then flips it. The result is always true or false.

    !"hello";   // false  ("hello" is truthy, flipped)
!0;         // true   (0 is falsy, flipped)
!!"hello";  // true   (two flips: same as Boolean("hello"))

    Where you will use this

    PatternCodeMeaning
    Default valueconst name = input || "Guest";Use input if it is truthy, otherwise "Guest"
    Guarduser && user.nameRead user.name only if user exists
    React rendering{isOpen && <Modal />}Show <Modal /> only when isOpen is truthy

    Common mistakes

    0 or "" as a real value. || replaces every falsy value, including ones you want to keep.

    const quantity = 0;
quantity || 1;   // 1, but 0 was a valid quantity
quantity ?? 1;   // 0, ?? only replaces null and undefined

    A 0 on screen in React. When the left side is 0, && returns 0, and React renders it.

    {items.length && <List />}      // shows "0" when the list is empty
{items.length > 0 && <List />}  // shows nothing when the list is empty

    The switch statement

    Comparing one value against many fixed options.

    switch compares one value against a list of case values using strict equality (===), and runs the code of the first match.

    1

    Syntax

    Each case ends with break. default runs when no case matches.

    const day = "wednesday";

switch (day) {
  case "monday":            // day === "monday"
    console.log("Team meeting");
    console.log("Plan the week");
    break;
  case "tuesday":
  case "wednesday":         // tuesday and wednesday share this code
    console.log("Focus work");
    break;
  case "saturday":
  case "sunday":
    console.log("Weekend");
    break;
  default:
    console.log("Not a valid day");
}
// Focus work
    2

    Why break matters

    Without break, JavaScript keeps running the code of the following cases until it reaches a break or the end. This is called fall-through. It is useful on purpose, as with tuesday and wednesday above, and a bug when forgotten.

    const level = 1;

switch (level) {
  case 1:
    console.log("Level 1");  // runs
  case 2:
    console.log("Level 2");  // also runs, no break above
    break;
  case 3:
    console.log("Level 3");  // does not run
}
    3

    The same logic with if / else

    Every switch can be written as if / else if. switch is easier to read when you compare one value against many fixed options.

    if (day === "monday") {
  console.log("Team meeting");
  console.log("Plan the week");
} else if (day === "tuesday" || day === "wednesday") {
  console.log("Focus work");
} else if (day === "saturday" || day === "sunday") {
  console.log("Weekend");
} else {
  console.log("Not a valid day");
}

    The ternary operator

    Choosing between two values in a single expression.

    const result = score >= 50 ? "Passed" : "Failed";

// same as:
let result;
if (score >= 50) {
  result = "Passed";
} else {
  result = "Failed";
}
    1

    Inside a template literal

    The ternary is an expression, so it works where if cannot. Use if / else when you need to run statements or have more than two outcomes.

    console.log(`Exam: ${score >= 50 ? "Passed" : "Failed"}`);  // Exam: Failed

    Core Part 2

    A first look at functions, arrays, objects and loops, plus strict mode. Later chapters cover each of these in depth.

      Strict mode

      Turning on stricter rules, so that silent mistakes become visible errors.

      'use strict'; as the first line of a script turns on strict mode for the whole file. Put it at the top of every script you write.

      1

      Turning it on

      It must be the very first statement in the file. Only comments may come before it. Anywhere else, it is ignored.

      'use strict';

const name = "Anna";
console.log(name);
      2

      Silent mistakes become errors

      Without strict mode, assigning to a misspelled variable name silently creates a new global variable. The bug goes unnoticed. With strict mode, it throws an error that points to the line.

      'use strict';

let hasDriversLicense = false;
const passedTest = true;

if (passedTest) hasDriverLicense = true;  // typo: "Driver" instead of "Drivers"
// without strict mode: creates a new global variable, no error
// with strict mode:    ReferenceError: hasDriverLicense is not defined

      This is the same rule as Forgetting the keyword on the let, const and var page.

      3

      Reserved words

      Strict mode reserves some words that JavaScript may use for future features, such as interface, private, public, package and protected. They cannot be used as variable names.

      'use strict';

const interface = "Audio";  // SyntaxError: Unexpected strict mode reserved word
const private = 534;        // SyntaxError

      JavaScript modules and classes always run in strict mode, even without the line.

      Functions

      Packaging code under a name, so you can run it again and again.

      A function is a reusable block of code. You define it once and call it whenever you need it. It can take input values and send a result back.

      1

      Defining and calling

      Calling, running and invoking all mean the same thing: writing the name followed by (). Without the parentheses, the function does not run.

      function greet() {
  console.log("Hello, I'm Anna");
}

greet();  // Hello, I'm Anna
greet();  // Hello, I'm Anna

      You have been calling functions all along: console.log(), Number() and String() are functions built into JavaScript.

      2

      Parameters and arguments

      Parameters are placeholders for the input. Arguments are the actual values you pass in when you call the function.

      TermWhat it isExample
      ParameterA name in the function definitionapples, oranges
      ArgumentA value passed in when calling5, 0
       
      function makeJuice(apples, oranges) {
  const juice = `Juice with ${apples} apples and ${oranges} oranges.`;
  return juice;
}

const appleJuice = makeJuice(5, 0);
console.log(appleJuice);        // Juice with 5 apples and 0 oranges.
console.log(makeJuice(2, 4));   // Juice with 2 apples and 4 oranges.

makeJuice(2);                   // a missing argument is undefined: "... and undefined oranges."
      3

      return

      return sends a value back to where the function was called. The call is then replaced by that value. return also ends the function immediately: code after it does not run.

      function calcAge(birthYear) {
  return 2030 - birthYear;
  console.log("Never runs");  // after return, nothing runs
}

const age = calcAge(1995);
console.log(age);  // 35

      A function without return gives back undefined. Logging a value is not the same as returning it.

      function logAge(birthYear) {
  console.log(2030 - birthYear);
}

const result = logAge(1995);  // logs 35
console.log(result);          // undefined, nothing was returned

      Function declarations vs expressions

      Two ways to write a function, and the one real difference between them.

      There are two ways to define a function with the function keyword:

      1. A declaration starts with function and a name.
      2. An expression is a function without a name, stored in a variable.
      1

      Side by side

      Both are called the same way and give the same result.

      // declaration
function calcAge1(birthYear) {
  return 2030 - birthYear;
}

// expression: an anonymous function stored in a variable
const calcAge2 = function (birthYear) {
  return 2030 - birthYear;
};

console.log(calcAge1(1995), calcAge2(1995));  // 35 35

      The expression version works because a function is a value, just like a number or a string. Functions are objects (see Values), and the right side of = is an expression that produces that value (see Statements and expressions).

      2

      Calling before defining

      A declaration can be called on a line above the one where it is defined. This is called hoisting. An expression cannot: the variable holding it does not have a value yet.

      console.log(calcAge1(1995));  // 35, works

function calcAge1(birthYear) {
  return 2030 - birthYear;
}

console.log(calcAge2(1995));  // ReferenceError: Cannot access 'calcAge2' before initialization

const calcAge2 = function (birthYear) {
  return 2030 - birthYear;
};

      Which one to use is mostly preference. Many developers prefer expressions, because they force you to define a function before you use it.

      Arrow functions

      A shorter way to write function expressions.

      An arrow function is a function expression written with => instead of the function keyword.

      1

      The one-line form

      When the body is a single expression, its value is returned automatically. No braces and no return.

      const calcAge3 = birthYear => 2030 - birthYear;
console.log(calcAge3(1995));  // 35

const calcAverage = (a, b, c) => (a + b + c) / 3;
console.log(calcAverage(3, 4, 5));  // 4
      ParametersSyntax
      Onex => x * 2
      Several(a, b) => a + b
      None() => "hi"
      2

      With a body

      For more than one line, use braces. Then return is required again.

      const yearsUntilRetirement = (birthYear, firstName) => {
  const age = 2030 - birthYear;
  const retirement = 65 - age;
  return `${firstName} retires in ${retirement} years`;
};

console.log(yearsUntilRetirement(1995, "Anna"));  // Anna retires in 30 years
console.log(yearsUntilRetirement(1980, "Marc"));  // Marc retires in 15 years

      Braces without return. With braces, nothing is returned automatically.

      const double = x => { x * 2 };  // returns undefined
const double2 = x => x * 2;     // returns x * 2
      3

      Three ways to write a function

      All three take input, run code and can return a value.

      KindSyntaxNotes
      Declarationfunction calc(y) { return 2030 - y; }Can be called before it is defined
      Expressionconst calc = function (y) { … };A function value stored in a variable
      Arrowconst calc = y => 2030 - y;Short, returns automatically, has no own this (see Object methods)
      4

      Example: functions working together

      Two teams play 3 rounds each. A team only wins if its average is at least double the other team's.

      const calcAverage = (a, b, c) => (a + b + c) / 3;

const checkWinner = function (avgDolphins, avgKoalas) {
  if (avgDolphins >= 2 * avgKoalas) {
    console.log(`Dolphins win (${avgDolphins} vs. ${avgKoalas})`);
  } else if (avgKoalas >= 2 * avgDolphins) {
    console.log(`Koalas win (${avgKoalas} vs. ${avgDolphins})`);
  } else {
    console.log("No team wins");
  }
};

checkWinner(calcAverage(85, 54, 41), calcAverage(23, 34, 27));
// Dolphins win (60 vs. 28)

      Arrays

      Storing a list of values in a single variable.

      An array is an ordered list of values. Each value has a position, called its index. The first index is 0.

      1

      Creating an array

      Write the values in square brackets, separated by commas.

      const friends = ["Lena", "Tom", "Marc"];
console.log(friends);  // ["Lena", "Tom", "Marc"]

const years = new Array(1995, 2012, 1998);  // also works, but rarely used

      Avoid new Array(). With a single number it behaves differently: new Array(3) creates 3 empty slots, not the array [3].

      2

      Reading values

      Put the index in square brackets. .length is the number of values, so the last index is always length - 1.

      friends[0];                   // "Lena", the first value
friends[2];                   // "Marc"
friends.length;               // 3
friends[friends.length - 1];  // "Marc", the last value
friends[5];                   // undefined, nothing at that index

      Any expression can go inside the brackets, like friends.length - 1 above.

      3

      Changing values

      Assign to an index to replace that value. This works on a const array: const only stops you from replacing the whole array.

      const friends = ["Lena", "Tom", "Marc"];

friends[2] = "Jay";
console.log(friends);  // ["Lena", "Tom", "Jay"]

friends = ["Bob", "Alice"];  // TypeError: Assignment to constant variable.

      See const on the let, const and var page.

      4

      Any values, including expressions

      An array can hold values of different types, other arrays, and expressions such as calculations and function calls. Each expression is replaced by its value.

      const firstName = "Anna";
const anna = [firstName, "Weber", 2030 - 1995, "designer", friends];
console.log(anna.length);  // 5

const calcAge = function (birthYear) {
  return 2030 - birthYear;
};
const years = [1995, 1967, 2012];
const ages = [calcAge(years[0]), calcAge(years[1]), calcAge(years[years.length - 1])];
console.log(ages);  // [35, 63, 18]

      Basic array methods

      Adding, removing and finding values in an array.

      A method is a function that belongs to a value. Arrays come with many built-in methods, called with a dot: friends.push("Jay").

      1

      Overview

      The first four change the array itself. Note what each one returns.

      MethodWhat it doesReturns
      push(x)Adds to the endThe new length
      unshift(x)Adds to the startThe new length
      pop()Removes the last valueThe removed value
      shift()Removes the first valueThe removed value
      indexOf(x)Finds a valueIts index, or -1 if not found
      includes(x)Checks for a valuetrue or false
      2

      Adding values

      const friends = ["Lena", "Tom", "Marc"];

const newLength = friends.push("Jay");
console.log(friends);    // ["Lena", "Tom", "Marc", "Jay"]
console.log(newLength);  // 4

friends.unshift("John");
console.log(friends);    // ["John", "Lena", "Tom", "Marc", "Jay"]
      3

      Removing values

      const popped = friends.pop();
console.log(popped);   // "Jay"

friends.shift();       // removes "John"
console.log(friends);  // ["Lena", "Tom", "Marc"]
      4

      Finding values

      includes uses strict equality (===), so the type must match too. It is the usual choice inside an if.

      friends.indexOf("Tom");   // 1
friends.indexOf("Bob");   // -1, not in the array

friends.push(23);
friends.includes("Tom");  // true
friends.includes(23);     // true
friends.includes("23");   // false, "23" is a string, not the number 23

if (friends.includes("Tom")) {
  console.log("You have a friend called Tom");
}

      Why === matters: see Equality.

      Objects

      Grouping related values under names instead of positions.

      An object stores key–value pairs. Each value has a name, called its key or property. Objects are written with curly braces.

      1

      Creating an object

      Write each property as key: value, separated by commas. A value can be anything: a string, a number, an expression, an array, another object.

      const anna = {
  firstName: "Anna",
  lastName: "Weber",
  age: 2030 - 1995,
  job: "designer",
  friends: ["Lena", "Tom", "Marc"]
};
      2

      Objects vs arrays

      The same data in an array only has positions. You have to remember that index 3 is the job. In an object, every value is labelled.

      const annaArray = ["Anna", "Weber", 35, "designer", ["Lena", "Tom", "Marc"]];
annaArray[3];  // "designer", but you have to know that 3 is the job

anna.job;      // "designer"
      UseForAccess by
      ArrayOrdered lists of similar valuesPosition: friends[0]
      ObjectNamed values that belong together; the order does not matterName: anna.job

      Dot vs bracket notation

      Two ways to read and write object properties.

      Use dot notation when you know the property name as you write the code. Use bracket notation when the name is computed or stored in a variable.

      1

      Reading a property

      Both give the same result. In brackets, the name is a string.

      anna.lastName;     // "Weber"
anna["lastName"];  // "Weber"
anna.middleName;   // undefined, the property does not exist
      2

      Computed names

      Brackets accept any expression, so the property name can be built while the code runs. The dot needs the real name.

      const nameKey = "Name";

anna["first" + nameKey];  // "Anna"
anna["last" + nameKey];   // "Weber"

anna."last" + nameKey;    // SyntaxError
      3

      A property chosen by the user

      prompt() returns the text the user typed, so the property name is only known while the code runs. Bracket notation is the only option here. The in operator checks whether the property exists.

      const key = prompt("What do you want to know? firstName, lastName, age, job or friends");

if (key in anna) {
  console.log(anna[key]);
} else {
  console.log("Wrong request!");
}

      Checking with if (anna[key]). This tests the value, not whether the property exists. A property with a falsy value, such as hasLicense: false or age: 0, would count as "Wrong request!". Same pitfall as 0 is a real value.

      4

      Adding properties

      Assigning to a property that does not exist yet creates it. Both notations work.

      anna.location = "Berlin";
anna["instagram"] = "@anna.weber";

console.log(`${anna.firstName} has ${anna.friends.length} friends, and her best friend is called ${anna.friends[0]}`);
// Anna has 3 friends, and her best friend is called Lena

      anna.friends.length is read from left to right: first anna.friends, then the length of that array.

      Object methods

      Functions stored in an object, and the this keyword.

      A method is a function stored as an object property. Inside a method, this is the object the method was called on.

      1

      Adding a method

      The value of the property is a function expression. You call it with a dot and parentheses.

      const anna = {
  firstName: "Anna",
  birthYear: 1995,
  job: "designer",
  hasLicense: true,

  calcAge: function (birthYear) {
    return 2030 - birthYear;
  }
};

anna.calcAge(1995);  // 35

      Array methods work the same way: arrays are objects, and push is one of their methods.

      2

      this

      Passing 1995 in is repetitive: the object already has the birth year. With this, the method reads it from the object it was called on, the one before the dot.

      calcAge: function () {
  return 2030 - this.birthYear;
}

anna.calcAge();  // 35, this is anna

      Why not write anna.birthYear? Because the method should not depend on the variable name. With this, the same method works on any object it is copied to.

      Arrow functions as methods. Arrow functions have no this of their own, so this is not the object.

      calcAge: () => 2030 - this.birthYear  // NaN, this is not anna
      3

      Storing a result on the object

      A method can create a new property with this. Calculate once, then read the stored value.

      calcAge: function () {
  this.age = 2030 - this.birthYear;
  return this.age;
}

anna.calcAge();  // 35, calculates and stores it
anna.age;        // 35, no new calculation
      4

      A method calling a method

      Inside a method, other methods of the same object are called with this too.

      getSummary: function () {
  return `${this.firstName} is a ${this.calcAge()}-year-old ${this.job}, and she has ${this.hasLicense ? "a" : "no"} driver's license.`;
}

anna.getSummary();
// "Anna is a 35-year-old designer, and she has a driver's license."

      Use this for every property. Mixing in anna.job works only as long as the object is called anna.

      5

      Example: the same method on two objects

      Each object calculates its own BMI with this. toFixed(1) rounds the result to one decimal for display.

      const mark = {
  fullName: "Mark Miller",
  mass: 78,
  height: 1.69,
  calcBMI: function () {
    this.bmi = this.mass / this.height ** 2;
    return this.bmi;
  }
};

const john = {
  fullName: "John Smith",
  mass: 92,
  height: 1.95,
  calcBMI: mark.calcBMI  // the same function, this is john when called on john
};

mark.calcBMI();
john.calcBMI();

if (mark.bmi > john.bmi) {
  console.log(`${mark.fullName}'s BMI (${mark.bmi.toFixed(1)}) is higher than ${john.fullName}'s (${john.bmi.toFixed(1)})`);
} else {
  console.log(`${john.fullName}'s BMI (${john.bmi.toFixed(1)}) is higher than ${mark.fullName}'s (${mark.bmi.toFixed(1)})`);
}
// Mark Miller's BMI (27.3) is higher than John Smith's (24.2)

      The for loop

      Repeating code a set number of times.

      A for loop runs its block again and again, as long as its condition is true. Each run is called an iteration.

      1

      Structure

      Instead of writing the same line 10 times, write it once and let the loop repeat it.

      for (let rep = 1; rep <= 10; rep++) {
  console.log(`Lifting weights repetition ${rep}`);
}
// Lifting weights repetition 1
// Lifting weights repetition 2
// ...
// Lifting weights repetition 10
      PartCodeWhen it runs
      Startlet rep = 1Once, before the first iteration
      Conditionrep <= 10Before each iteration. When it is false, the loop stops
      Updaterep++After each iteration

      If the condition never becomes false, the loop never ends and the page freezes. This is an infinite loop.

      Looping arrays, break and continue

      Going through every value in an array, and controlling when a loop skips or stops.

      To loop over an array, count the index from 0 up to length - 1, and read array[i] in each iteration.

      1

      Reading every value

      The condition is i < anna.length, not <=: the last index is one less than the length.

      const anna = ["Anna", "Weber", 2030 - 1995, "designer", ["Lena", "Tom"], true];
const types = [];

for (let i = 0; i < anna.length; i++) {
  console.log(anna[i], typeof anna[i]);
  types.push(typeof anna[i]);
}

console.log(types);
// ["string", "string", "number", "string", "object", "boolean"]

      Using anna.length instead of the number 6 means the loop still works when values are added or removed.

      2

      Building a new array

      Start with an empty array and push a result in each iteration.

      const years = [1995, 2012, 1969, 2020];
const ages = [];

for (let i = 0; i < years.length; i++) {
  ages.push(2030 - years[i]);
}
console.log(ages);  // [35, 18, 61, 10]

      The same pattern fills several arrays at once. Here a tip is 15% for bills between 50 and 300, and 20% otherwise:

      const calcTip = bill => bill >= 50 && bill <= 300 ? bill * 0.15 : bill * 0.2;

const bills = [22, 295, 176, 440, 37, 105, 10, 1100, 86, 52];
const tips = [];
const totals = [];

for (let i = 0; i < bills.length; i++) {
  const tip = calcTip(bills[i]);
  tips.push(tip);
  totals.push(bills[i] + tip);
}
      3

      Adding up values

      Start a sum at 0 and add each value to it. Dividing by the length gives the average.

      const calcAverage = function (arr) {
  let sum = 0;
  for (let i = 0; i < arr.length; i++) {
    sum += arr[i];
  }
  return sum / arr.length;
};

console.log(calcAverage([2, 3, 7]));  // 4
console.log(calcAverage(totals));     // the average total of the bills above
      4

      continue

      continue skips the rest of the current iteration and goes on with the next one.

      for (let i = 0; i < anna.length; i++) {
  if (typeof anna[i] !== "string") continue;
  console.log(anna[i]);
}
// Anna
// Weber
// designer
      5

      break

      break stops the whole loop immediately.

      for (let i = 0; i < anna.length; i++) {
  if (typeof anna[i] === "number") break;
  console.log(anna[i]);
}
// Anna
// Weber
// stops at 35, the first number

      Looping backwards and nested loops

      Counting down instead of up, and running a loop inside another loop.

      All three parts of a for loop can be changed: where it starts, when it stops and how it counts.

      1

      Looping backwards

      Start at the last index, stop after index 0, and count down with i--.

      const friends = ["Lena", "Tom", "Marc"];

for (let i = friends.length - 1; i >= 0; i--) {
  console.log(i, friends[i]);
}
// 2 Marc
// 1 Tom
// 0 Lena
      2

      A loop inside a loop

      The inner loop runs completely in every iteration of the outer loop.

      for (let exercise = 1; exercise <= 3; exercise++) {
  console.log(`--- Starting exercise ${exercise}`);

  for (let rep = 1; rep <= 5; rep++) {
    console.log(`Exercise ${exercise}: repetition ${rep}`);
  }
}
// 3 exercises × 5 repetitions = 15 repetitions in total

      The while loop

      Repeating code while a condition is true, when you don't know the number of iterations in advance.

      A while loop only has a condition. It runs its block as long as the condition is true.

      1

      With a counter

      The same loop as the for example. The start and the update are now separate lines that you write yourself.

      let rep = 1;

while (rep <= 10) {
  console.log(`Lifting weights repetition ${rep}`);
  rep++;  // without this line, rep stays 1 and the loop never ends
}
      2

      When the number of iterations is unknown

      Roll a die until it shows a 6. It could take one roll or twenty, so a while loop fits better than a for loop.

      let dice = Math.trunc(Math.random() * 6) + 1;

while (dice !== 6) {
  console.log(`You rolled a ${dice}`);
  dice = Math.trunc(Math.random() * 6) + 1;
  if (dice === 6) console.log("Loop is about to end...");
}
      StepResult
      Math.random()A random decimal from 0 up to (not including) 1
      * 6From 0 up to (not including) 6
      Math.trunc(…)Cuts off the decimals: 0 to 5
      + 11 to 6

      If the first roll is already a 6, the condition is false from the start and the loop body never runs.

      3

      for or while?

      LoopUse whenExample
      forYou know how many iterations you needEvery value in an array, 10 repetitions
      whileIt depends on something that happens during the loopRolling until a 6, asking until the input is valid
